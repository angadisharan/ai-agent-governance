# Contributing

## Principles

Changes to governance policies can affect every adopting project. Keep rules clear, testable, minimally ambiguous, and consistent across files.

## Change process

1. Describe the risk or engineering problem.
2. Identify affected policies and agent adapters.
3. Propose exact wording and rationale.
4. Assess compatibility and possible unintended effects.
5. Obtain review from the designated repository owner/security reviewer.
6. Update related checklists and enforcement documentation.
7. Validate internal links, policy references, and examples.
8. Record significant policy changes in the pull request or change proposal.

## Exceptions

Exceptions must be explicit, narrowly scoped, time-bounded where appropriate, approved by an authorised owner, and documented. An exception must not grant broader access than necessary or expose secrets unintentionally.

## Do not contribute

- Credentials, tokens, private keys, production connection strings, or real personal data.
- Instructions that encourage bypassing security controls.
- Unreviewed scripts that access remote systems or modify infrastructure.
- Claims that policy text alone technically enforces access restrictions.
