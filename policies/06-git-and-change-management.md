# Git and Change Management

Follow the repository's filesystem policy. If hidden Git metadata is prohibited, do not inspect it or run commands requiring access to it.

Without explicit approval, do not commit, push, tag, release, force-push, reset, clean, rebase, amend, or rewrite history. Do not overwrite user changes. Do not modify CI/CD permissions or branch protections without review.

Keep diffs small and reviewable. Explain material changes and risks. Obtain review for security-sensitive, architectural, database, dependency, and deployment changes. Never claim a commit, push, or release succeeded unless authorised and verified.
